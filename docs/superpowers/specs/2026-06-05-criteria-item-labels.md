# 평가항목 라벨링 & LLM 요약 지시

> 목적: 항목별 A/B 라벨 확정 + B 항목의 LLM 증거 정제 방식 설계  
> 작성일: 2026-06-05  
> 상태: **초안 — 검토 필요**

## 라벨 정의

| 라벨 | 의미 | LLM 역할 |
|------|------|---------|
| **A** | 기술 증거만으로 판정 가능 | 양호/취약/판단보류 판정 |
| **B** | 담당자 인터뷰 필수 (업무필요성 확인) | 증거 요약 + 인터뷰 체크리스트 생성, verdict=판단보류 고정 |

## DB 공통 항목 (DBM-xxx)

### DBM-001 — 비밀번호 강도

- **라벨**: A
- **증거 형식**: `{"USER": "admin", "AUTHENTICATION_STRING": "<REDACTED len=67>"}`
- **판정 방식**: 해시 알고리즘(PLUGIN) 확인. 빈 값이면 비밀번호 없음. 실제 복잡도는 크랙 불가 → 대부분 판단보류
- **LLM 지시**: 현행 유지

---

### DBM-003 — 업무상 불필요한 계정

- **라벨**: **B**
- **증거 형식**: `{"HOST": "%", "USER": "test", "PLUGIN": "...", "ACCOUNT_LOCKED": "N"}`
- **정제 방향**:
  - 활성 계정(ACCOUNT_LOCKED=N)과 잠긴 계정(Y) 분리 집계
  - 시스템 내장 계정(rdsadmin, mysql.sys, mariadb.sys, rds_superuser_role 등) 별도 표시
  - 의심 계정명 패턴(test, temp, old, backup 포함) 하이라이트
- **LLM 요약 지시 초안**:
  ```
  증거의 계정 목록을 다음 형식으로 요약하라. 판정하지 말 것.
  - 활성 계정(ACCOUNT_LOCKED=N): [계정@호스트 목록]
  - 잠긴 계정(ACCOUNT_LOCKED=Y): [목록]
  - 시스템 내장 계정으로 추정: [rdsadmin/mysql.sys 등 목록]
  - 검토 권장 계정(test/temp/old 등 이름): [목록]
  2~3문장 요약 후 "담당자 인터뷰를 통해 불필요 계정 여부 확인 필요"로 마무리.
  ```
- **검토 필요**: 시스템 내장 계정 목록 DBMS별 차이 있음. 자동 필터링 vs LLM에 위임 중 선택 필요

---

### DBM-004 — 업무상 불필요한 관리자 권한

- **라벨**: **B**
- **증거 형식**: `{"GRANTEE": "'admin'@'%'", "PRIVILEGE_TYPE": "ALTER"}` (계정당 N행)
- **정제 방향**:
  - 계정별 권한 목록을 집계 (행 단위 → 계정 단위로 묶기)
  - USAGE만 있는 계정(일반 사용자)은 제외 또는 별도 표시
  - 권한 개수가 많은 순으로 정렬
- **LLM 요약 지시 초안**:
  ```
  증거의 권한 행을 계정별로 집계하여 요약하라. 판정하지 말 것.
  - 각 계정과 보유 권한 수, 대표 권한명 나열 (예: admin@% — 27개: ALTER, CREATE, DROP 등)
  - USAGE만 있는 계정은 "(일반 권한만)" 으로 표시
  마지막에 "각 계정의 권한이 업무상 모두 필요한지 담당자 인터뷰 확인 필요" 한 줄 추가.
  ```
- **검토 필요**: 행이 100개 넘는 경우 있음 (Oracle DBM-004 136행). 토큰 절감 위해 집계를 코드에서 전처리할지 검토

### DBM-005 — 중요정보 암호화

- **라벨**: A
- **증거 형식**: `{"TABLE_SCHEMA": "...", "TABLE_NAME": "...", "COLUMN_NAME": "password", "RESULT": "<REDACTED 평문추정 len=41>"}`
- **판정 방식**: RESULT가 `<REDACTED 평문추정>` 이면 취약, `<REDACTED len=N>` (해시) 이면 양호

### DBM-007 — 비밀번호 복잡도

- **라벨**: A
- **증거 형식**: 플러그인 설정값 (validate_password_length, policy 등)
- **판정 방식**: length·policy·count 조합으로 기준 충족 여부
- **LLM 지시**: 현행 유지. 단 "설정값 조합 전체를 보고 판단" 명시 필요 (14b 오류 방지)

---

### DBM-008 — 비밀번호 변경 주기

- **라벨**: A
- **증거 형식**: `default_password_lifetime` 설정값
- **판정 방식**: 90일(분기) 이하 설정 여부
- **LLM 지시**: 현행 유지. "설정값 존재 ≠ 기준 충족" 명시

---

### DBM-009 — 세션 타임아웃

- **라벨**: A
- **증거 형식**: wait_timeout, interactive_timeout (초 단위), PostgreSQL은 ms 단위
- **판정 방식**: 900초(15분) 이하 여부. **단위 주의**
- **LLM 지시**: few-shot에 단위 예시 포함. PostgreSQL은 known_units로 ms 명시

### DBM-015 — PUBLIC 권한

- **라벨**: A (기술적으로 판단 가능)
- **증거 형식**: PUBLIC에 부여된 권한 목록

### DBM-016 — 최신 보안패치

- **증거 형식**: 버전 정보
- **한계**: 최신 여부는 벤더 릴리즈 사이클 지식 필요 → 로컬 LLM 한계
- **LLM 지시**: 현행 유지 (보류 처리)

### DBM-017 — 불필요한 시스템 테이블 접근 권한

- **라벨**: **B**
- **증거 형식**: `{"GRANTEE": "...", "PRIVILEGE_TYPE": "...", "TABLE_NAME": "DBA_USERS"}` (Oracle) 또는 스키마 권한 (MariaDB/PG)
- **정제 방향**:
  - 계정/역할별로 접근하는 시스템 테이블 목록 집계
  - 시스템 내장 역할(DBA, SELECT_CATALOG_ROLE 등)은 제외
- **LLM 요약 지시 초안**:
  ```
  증거의 시스템 테이블 접근 권한을 계정/역할별로 집계하여 요약하라. 판정하지 말 것.
  - 각 계정/역할과 접근하는 시스템 테이블명, 권한 유형 나열
  마지막에 "각 접근 권한의 업무 필요성 담당자 인터뷰 확인 필요" 추가.
  ```

### DBM-020 — 계정 분리 (사용자별)

- **라벨**: **B**
- **증거 형식**: `{"USER": "admin", "HOST": "%", "PLUGIN": "..."}` (계정 목록)
- **정제 방향**:
  - 로그인 가능 계정 목록 나열 (시스템 계정 제외)
  - 공유 계정 의심 패턴(admin, operator, dba 등 공용명) 표시
- **LLM 요약 지시 초안**:
  ```
  계정 목록을 요약하라. 판정하지 말 것.
  - 로그인 가능 계정: [목록]
  - 시스템/내장 계정으로 추정: [목록]
  마지막에 "각 계정이 사용자 1인당 1계정으로 운영되는지, 공유 계정은 없는지 담당자 인터뷰 확인 필요" 추가.
  ```

### DBM-024 — WITH GRANT OPTION

- **라벨**: **B**
- **증거 형식**: `{"GRANTEE": "...", "PRIVILEGE_TYPE": "...", "IS_GRANTABLE": "YES"}` 또는 빈 결과(empty_means_good)
- **정제 방향**:
  - GRANT OPTION 보유 권한을 계정별로 집계
  - 빈 결과면 "GRANT OPTION 없음 확인" 으로 요약 → 양호 처리 가능 (empty_means_good)
- **LLM 요약 지시 초안**:
  ```
  IS_GRANTABLE=YES 권한을 계정별로 집계하여 요약하라. 판정하지 말 것.
  - 각 계정과 GRANT OPTION 보유 권한 목록 나열
  마지막에 "해당 권한들이 운영상 모두 필요한지 담당자 인터뷰 확인 필요" 추가.
  ```
- **검토 필요**: empty_means_good 항목은 B가 아닌 A로 처리 (빈 결과 = 양호 자동 판정)

## 클라우드 항목 (PISM-xxx)

### PISM-023 — 업무상 불필요한 가상자원

- **라벨**: **B**
- **증거 형식**: Lambda 함수 목록 (이름, 런타임, 최종수정일) + S3 버킷 목록
- **정제 방향**:
  - Lambda: 함수명, 런타임, 마지막 수정일 요약
  - S3: 버킷 수, 생성일 범위
- **LLM 요약 지시 초안**:
  ```
  Lambda 함수 및 S3 버킷 목록을 요약하라. 판정하지 말 것.
  - Lambda 함수: [이름, 런타임, 마지막수정일] 목록
  - S3 버킷: 총 N개, 생성일 범위
  마지막에 "각 자원이 현재 업무에 사용 중인지 담당자 인터뷰 확인 필요" 추가.
  ```
