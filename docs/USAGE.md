# judge_tool 사용 안내 (비개발자용)

전자금융기반시설 보안 점검 결과를 자동으로 판정하는 도구입니다. 아래 3단계만
따라 하면 됩니다. (개발자용 지침은 `CLAUDE.md` 참조 — 이 문서와 별개입니다.)

## 0. 준비물 확인

- 이 저장소 폴더 전체(`judge_tool/`, `ref/`, `judge.sh` 등이 들어 있는 폴더)
- 점검 결과 파일(xml/json/xlsx 등, 점검 스크립트가 만들어 준 파일)
- 인터넷이 안 되는 폐쇄망이어도 동작합니다(로컬 LLM만 사용).

## 1단계 — 의존성 아카이브 해제

담당자에게 받은 파이썬 의존성 아카이브(예: `deps.tar.gz` 또는 `wheelhouse/`)를
이 저장소 폴더 기준으로 풀어 놓습니다. 이미 `openpyxl`, `requests` 등이 설치된
환경(회사 표준 파이썬)이라면 이 단계는 건너뛰어도 됩니다.

```bash
# 예시(실제 배포 방식은 담당자 안내를 따르세요)
tar -xzf deps.tar.gz -C .
# 또는: python3 -m pip install --no-index --find-links=wheelhouse -r requirements.txt
```

설치가 잘 됐는지 확인:

```bash
python3 -c "import openpyxl, requests; print('OK')"
```

## 2단계 — Ollama 모델 준비

이 도구는 로컬에서 실행되는 Ollama(LLM 서버)를 사용합니다. 아래 순서로
설치·기동·모델 준비를 합니다.

```bash
# 1) Ollama가 없다면 설치(최초 1회, https://ollama.com 참조)
# 2) 서버 기동(터미널 하나를 계속 띄워 두거나 백그라운드 서비스로 등록)
ollama serve

# 3) 다른 터미널에서 모델 다운로드(최초 1회, 폐쇄망이면 오프라인 모델 파일을
#    담당자에게 받아 `ollama create`로 등록)
ollama pull qwen3-coder:30b
```

준비가 됐는지는 judge_tool이 실행 시 자동으로 확인합니다. Ollama가 꺼져
있거나 모델이 없으면 실행 즉시(판정 도중이 아니라) 아래처럼 명확히 안내하고
멈춥니다:

```
오류: [Ollama 확인 실패] ... Ollama가 실행 중인지 확인하세요: `ollama serve`,
`ollama pull qwen3-coder:30b`.
```

## 3단계 — judge.sh 실행

### (A) 대화형 모드 — 인자 없이 실행 (가장 쉬움)

```bash
./judge.sh
```

- 결과 파일이 들어 있는 폴더를 물어봅니다(엔터를 누르면 현재 폴더).
- 폴더 안 후보 파일 목록과 **자동 추정된 프로파일**을 번호와 함께 보여줍니다.
- 번호를 입력해 판정할 파일을 고릅니다.
- 추정된 프로파일이 맞으면 엔터, 다르면 직접 입력합니다.
- 판정이 끝나면 `out/` 폴더(또는 안내된 경로)에 결과 파일(`.json`, `.xlsx`)이
  생성됩니다.

### (B) 파일 하나 바로 판정

```bash
./judge.sh <결과파일>
# 예: ./judge.sh /data/mysql_result_rds.json
```

평가기준 파일(`--criteria`)과 프로파일(`--profile`)을 지정하지 않아도
`ref/` 폴더의 평가기준 파일과 파일명을 보고 자동으로 채워 줍니다. 파일명만
봐서는 어떤 프로파일인지 애매한 경우(예: `.xml` 확장자만으로는 서버/네트워크/
방화벽 등 여러 후보가 있음)에는 후보 목록을 보여주고 멈추므로, 이때는
`--profile` 값을 추가해 다시 실행하면 됩니다:

```bash
./judge.sh --report host01-s-20260101.xml --profile server
```

### (C) 폴더째 한 번에 판정(배치)

```bash
./judge.sh --report /data/점검결과폴더
```

폴더 안의 결과 파일들을 하나씩 자동으로 프로파일을 추정해 순서대로 판정합니다.
파일 하나가 실패해도(손상 파일 등) 나머지 파일은 계속 처리되며, 마지막에
파일별 성공/실패 요약이 한 줄씩 출력됩니다.

## 결과 확인

기본적으로 결과는 저장소 폴더의 `out/` 아래에 저장됩니다:

- `result_<파일명>.json` — 기계가 읽는 원본 판정 결과
- `result_<파일명>.xlsx` — 사람이 검토하는 엑셀 표(판정/근거/검토 필요 여부)

`needs_review=True`(엑셀에서 강조 표시)인 행은 사람이 한 번 더 확인해야 하는
항목입니다.

## 자주 겪는 문제

| 증상 | 원인/해결 |
|---|---|
| `Ollama 확인 실패` | `ollama serve`가 안 떠 있거나 모델(`qwen3-coder:30b`)이 없음 → 2단계 다시 확인 |
| `--profile을 확정할 수 없습니다` | 파일명만으로 프로파일을 판단할 수 없음 → 안내된 후보 중 하나를 `--profile`로 직접 지정 |
| `--criteria가 지정되지 않았고 ... 자동으로 찾지 못했습니다` | `ref/` 폴더에 평가기준 xlsx가 없음 → `--criteria <경로>`로 직접 지정 |
| `출력 디렉터리가 입력 데이터 디렉터리와 같습니다` | 결과를 원본 점검 데이터 폴더에 덮어쓰지 못하게 막는 안전장치 → `--out-dir`로 별도 폴더 지정 |

## 참고: 기존 방식(명시적 인자)도 그대로 동작합니다

```bash
python3 -m judge_tool --report <결과파일> --criteria <평가기준.xlsx> \
  --profile <cloud|db_mysql|server|...> --out-dir out
```

## (D) 웹 UI 모드 — 여러 건을 프로젝트 단위로 관리하고 싶을 때

여러 자산(점검 결과 파일)을 한 점검 건(프로젝트)으로 묶어 브라우저에서
업로드·프로파일 지정·판정 실행·결과 확인까지 하고 싶으면 웹 UI 모드를
씁니다. CLI와 동일한 판정 엔진을 그대로 재사용하며, **로컬(127.0.0.1)에서만
접속되는 대외비 도구**입니다(외부 네트워크 노출 없음, Ollama도 localhost만
사용).

```bash
./judge.sh --web
# 또는: python3 -m judge_tool.webui
```

기동하면 아래처럼 접속 주소와 저장 위치를 안내합니다:

```
접속 주소     : http://127.0.0.1:8765
저장 위치     : <저장소 폴더>/judge_projects
주의(대외비)   : 이 서버는 127.0.0.1(로컬)에서만 접속됩니다. 외부 노출 금지.
종료하려면 Ctrl+C 를 누르세요.
```

브라우저에서 안내된 주소(`http://127.0.0.1:8765`)를 열어 사용합니다.

### 사용 흐름

1. 왼쪽 사이드바에서 **새 프로젝트**(점검 건)를 만듭니다.
2. 점검 결과 파일들을 드래그앤드롭(또는 클릭 선택)으로 업로드합니다 —
   업로드된 파일 각각이 "자산"이 되며, 파일명으로 프로파일이 자동 추정됩니다.
3. 자동 추정이 안 된 자산(빨간 표시)은 목록에서 프로파일/변형을 직접 선택합니다.
4. 자산별 **판정 실행**(또는 **전체 판정 실행**)을 누르면 백그라운드에서
   순차로 판정이 진행됩니다(진행 상태·경과시간이 표시됩니다).
5. 완료된 자산은 **결과 보기**로 요약(양호/취약/판단보류/재검토), 담당자
   인터뷰 필요 항목, 항목별 판정·근거를 확인하거나 엑셀로 다운로드합니다.

### 자주 쓰는 옵션

```bash
./judge.sh --web --port 9000                     # 다른 포트로 기동
./judge.sh --web --project-root /data/judge_wk    # 저장 위치 변경(기본: 저장소/judge_projects)
./judge.sh --web --token my-secret-token          # 같은 PC의 다른 사용자로부터 보호(선택)
```

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--host` | `127.0.0.1` | 다른 값을 주면 대외비 보호를 위해 즉시 종료됩니다(변경 불가). |
| `--port` | `8765` | 바인딩 포트 |
| `--project-root` | `<저장소>/judge_projects` | 프로젝트/자산/결과 저장 위치. `results/` 디렉터리와 같거나 그 하위면 기동을 거부합니다. |
| `--ollama-url` | `http://localhost:11434` | CLI와 동일 |
| `--model` | `qwen3-coder:30b` | CLI와 동일 |
| `--criteria` | (자동탐색) | 평가기준 xlsx 직접 지정 |
| `--token` | (없음) | 지정 시 `/api/*` 요청에 `X-Auth-Token` 헤더(또는 URL `?token=`)가 일치해야 합니다. |
| `--max-upload-mb` | `50` | 자산 1건 업로드 용량 상한(MB) |

주의: 프로젝트/자산 데이터는 `--project-root`(기본 `judge_projects/`)에
디스크로 저장되어 서버를 껐다 켜도 유지됩니다. `results/`(대외비 실데이터
디렉터리)는 웹 UI가 절대 읽거나 쓰지 않습니다.
